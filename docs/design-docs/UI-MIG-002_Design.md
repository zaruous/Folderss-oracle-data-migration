# UI-MIG-002. 테이블 매핑

## 1. 화면 내용 요약

- **목적**: 원본과 대상 테이블을 잇는다. 원본은 **테이블** 또는 **SQL(SELECT 문)** 이다. 이름·구조가 달라도 되고(`SRC_CUSTOMER → TB_MEMBER`), SQL 원본이면 JOIN·집계 결과를 테이블처럼 옮긴다(`SQL SQLMAP_MEMBER → TB_MEMBER`). 매핑마다 이관 방식과 병합 키를 정한다.
- **주요 기능**:
  - 매핑 그리드: 사용 · 원본(테이블 · SQL) · 행 수 · 대상 테이블 · 이관 방식 · 병합 키 · 컬럼 매핑 비율 · 상태
  - 이관 방식: `INSERT ONLY` · `INSERT + UPDATE`(MERGE) · `TRUNCATE + INSERT` · `DELETE + INSERT`
  - 매핑 추가(팝업, 원본 종류 선택 · 이름 추천) · SQL 원본 추가 · 삭제 · 이름으로 자동 매칭(팝업, 근거 표시) · JSON 가져오기/내보내기
  - 스키마 탐색: 원본·대상 테이블 목록과 매핑 여부(SQL 원본이 읽는 테이블도 표시), 매핑 안 된 원본에서 바로 [+ 매핑]
  - 행을 두 번 누르거나 [편집 ›] → 컬럼 매핑(UI-MIG-003), SQL 원본 이름 → SQL 원본 편집기(UI-MIG-004, 도구 창)

## 5. 기타 특이사항

- **유효성 검사**:
  - 같은 테이블 원본→대상 매핑은 한 번만. 한 원본을 여러 대상에 쓰는 것은 허용(팝업 ①의 "이미 매핑함(다른 대상에 또)" 그룹). SQL 원본 이름은 작업 안에서 겹칠 수 없음.
  - 키가 필요한 방식(MERGE·DELETE+INSERT)에 병합 키가 없으면 상태 `ERROR`.
  - 상태 열: 컬럼 검사(UI-MIG-003) 중 가장 나쁜 수준 — `OK`(PASS·INFO) · `WARN` · `ERROR`, 아래에 "오류 n / 경고 n". SQL 원본의 SQL이 해석되지 않으면 `ERROR`와 함께 오류 문장을 원본 칸에 보임.
  - SQL 원본의 행 수는 `~390,325`처럼 추정값(주 테이블 통계 − 체크포인트 조건)으로 보이고, 정확한 값은 UI-MIG-004 FUNC07.
- **권한 처리**: 화면 자체는 메타데이터 캐시만 쓴다. FUNC06은 원본 SELECT 권한 필요.
- **팝업**: ① 매핑 추가(원본 종류 테이블·SQL), ② 이름으로 자동 매칭, 삭제 확인 — 모두 위에 제목, 아래 오른쪽에 [취소]·[주 버튼]. Esc = 취소, Enter = 주 버튼(입력칸 밖).
- **기타**:
  - 원본을 SQL로 쓰는 경우: 다른 테이블과 JOIN해야 채울 수 있는 대상 컬럼(예: `MEMBER_GRADE` ← 등급 테이블의 이름), 코드 테이블 조회, 집계(GROUP BY), 여러 원본 → 대상 하나, 필터가 복잡한 경우.
  - 용어 사전(테이블·컬럼)은 매핑 템플릿에 함께 저장해 다음 작업에서 다시 쓴다(UI-MIG-007).
  - 이관 방식 선택 기준: 대상이 비었으면 `INSERT ONLY`(가장 빠름), 기존 행이 있으면 `INSERT + UPDATE`(다시 실행해도 중복 없음), 코드·기준 테이블처럼 작고 통째로 바꿀 것은 `TRUNCATE + INSERT`, 키 범위만 갈아 끼울 때 `DELETE + INSERT`.
  - `INSERT ONLY`인데 대상에 행이 있으면 검증에서 "같은 키는 ORA-00001로 거부" 경고(UI-MIG-005).
  - 너비가 좁으면(1560px 이하) 스키마 탐색은 그리드 아래로 내려가고 원본·대상 목록을 나란히 둔다.
